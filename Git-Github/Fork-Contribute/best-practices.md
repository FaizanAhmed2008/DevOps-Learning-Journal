# Best Practices for Open Source

## Before Contributing

✅ Read **CONTRIBUTING.md** in the repo
✅ Follow the project's **code style**
✅ Check **existing issues** to avoid duplicates
✅ Start with **small contributions** (docs, typos, simple bugs)

## During Development

✅ Create **focused PRs** - one feature per PR
✅ Keep commits **clean and organized**
✅ Write **clear commit messages**
✅ **Test thoroughly** before pushing
✅ **Sync regularly** with upstream
✅ Update **documentation** if needed

## PR Guidelines

✅ **Small PRs** = Faster reviews
✅ **Clear description** of changes
✅ **Link related issues** (#123)
✅ **Screenshot/demo** if visual changes
✅ **Be patient** - maintainers volunteer

## Communication

✅ Be **respectful** and **polite**
✅ Accept **constructive criticism**
✅ Ask **questions** if unclear
✅ Thank maintainers for review
✅ Learn from **feedback**

## What NOT to Do

❌ Don't code on `main` branch
❌ Don't make massive PRs with many changes
❌ Don't ignore review comments
❌ Don't force-push to shared branches
❌ Don't get discouraged by rejections

## Commit Message Examples

**Good:**
```
Add user authentication feature
Fix #123: Resolve login timeout issue
Update README with setup instructions
Refactor database query for performance
```

**Bad:**
```
Fixed stuff
updated
changes
WIP
```

## Tips for Success

1. **Contribute consistently** - Multiple small PRs > One massive PR
2. **Start with docs** - Easy way to help and get familiar
3. **Communicate early** - Discuss big changes before coding
4. **Review others' code** - Learn and help the community
5. **Celebrate merges** - You're now an open source contributor! 🎉
